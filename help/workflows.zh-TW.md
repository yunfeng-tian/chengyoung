# 工作流程

工作流程是一份保存下來的 YAML 檔案，用來描述一件任務：模型收到的指令、這次工作階段可以使用的擴充，以及執行如何開始。當某件事會反覆做、且你希望每次結果形狀一致時，就適合寫成工作流程。

## 工作流程保存在哪裡

| 位置 | 生效範圍 |
| --- | --- |
| 設定目錄下的 `recipes/` | 本機所有工作階段 |
| 工作目錄下的 `.goose/recipes/` | 在該目錄中執行的工作階段 |
| 工作目錄或使用者主目錄下的 `.agents/recipes/` | 面向代理的通用約定 |

在介面裡新建的工作流程會寫入設定目錄，因此每個工作階段都能看到它。

## 常用欄位

```yaml
version: 1.0.0
title: 發佈前檢查
description: 發佈前對儲存庫做一次複核
instructions: 你是一名嚴謹的發佈複核者，請用簡短清單回報發現的問題。
prompt: 複核這個儲存庫，列出你發現的風險。
extensions:
  - developer
settings:
  temperature: 0.2
  max_turns: 20
parameters:
  - key: target
    input_type: string
    requirement: required
    description: 要核驗的版本號
```

- `instructions` 是本次執行的長期指令；`prompt` 是第一則訊息。
- `extensions` 限定這次工作階段可用的擴充，工作流程因此不會觸碰到它不需要的工具。
- `settings` 可固定供應方、模型、`temperature` 與 `max_turns`。
- `parameters` 把工作流程變成一張小表單：執行時再填具體取值。
- `response` 可要求固定的 JSON 結構，`sub_recipes` 可呼叫另一份工作流程檔案。

## 建立、執行與重複使用

1. 在輸入框或工作流程頁面新建工作流程。
2. 先描述目標，需要精確欄位名稱時直接編輯 YAML。
3. 在工作流程清單裡執行它，或帶著它開啟一段工作階段繼續打磨。
4. 把這次執行保存為工作階段，之後可在工作階段歷史裡找回。

工作流程還可以用連結攜帶（`goose://recipe?config=...`，整份定義在連結片段裡），適合在團隊內分享。

## 工作流程、技能與應用

| 概念 | 說明 |
| --- | --- |
| 工作流程 | 保存下來的任務定義，由你主動執行 |
| 技能 | 主題相符時 ChengYoung 自動帶入工作階段的可重複使用指引 |
| 應用 | 為特定任務產生的小介面 |
| 調度 | 由計時器而非手動觸發的工作流程 |
